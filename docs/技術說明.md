## 頁面怎麼產生

網站使用 **React Router 7 的框架模式**。每一頁送到瀏覽器的都是**完整的 HTML**，JavaScript 載入後只負責互動（輪播、選單、動畫）。依內容性質分成兩種產生方式：

| 方式 | 哪些頁面 | 什麼時候產生 | 設定在哪 |
|---|---|---|---|
| **預先產生**（prerender） | 關於、計畫、展覽、工作坊、市集、講座、戶外電影、報名、聯絡 | 執行 `npm run build` 時就產生成 HTML 檔 | `react-router.config.js` 的 `STATIC_PAGES`（展覽、工作坊內頁依 JSON 自動加入） |
| **伺服器即時產生**（SSR） | 首頁、文章總覽、文章內頁、404、後台 | 每次有人瀏覽時 | 不在上面清單裡的頁面都是這種 |

判斷原則：**內容寫在程式或 JSON 裡的 → 預先產生；內容來自資料庫的 → 即時產生**。首頁因為有「最新報導」區塊，所以是即時產生，後台一發文首頁就會更新。

### 一次請求的流程（`server/index.js`）

```
請求進來
 ├─ /api/login、/api/articles…  → 文章 API（後台用）
 ├─ /uploads/…                  → 後台上傳的海報圖
 ├─ /assets/…                   → 打包好的 JS / CSS / 圖片（檔名含雜湊，瀏覽器長期快取）
 ├─ 有預先產生的 HTML？          → 直接送出 build/client/<路徑>/index.html
 └─ 其他                         → React Router 即時產生 HTML
                                    （執行該頁的 loader → 渲染元件 → 送出）
```

開發模式（`npm run dev`）沒有預先產生的檔案，所有頁面都即時產生，並由 Vite 提供熱更新。

## 頁面檔可以匯出什麼

路由表在 `src/routes.js`（網址 → 頁面檔）。每個頁面檔除了預設匯出的元件，還可以匯出：

| 匯出 | 用途 | 例子 |
|---|---|---|
| `meta` | 這一頁的描述、分享標題與預覽圖 | 每個頁面檔最上方 |
| `loader` | 在伺服器端準備這一頁要的資料，元件用 `loaderData` 取得 | `Main.jsx`、`ArticlesPage.jsx`、`SingleArticlePage.jsx` |

`loader` 裡的 `context.articles` 由 `server/index.js` 的 `getLoadContext` 提供，直接查資料庫（`server/articles.js`），不必繞一圈打自己的 API。找不到資料時用 `data(..., { status: 404 })` 回傳 404 狀態碼。

## 資料怎麼流動

| 資料 | 存在哪 | 誰讀 | 怎麼改 |
|---|---|---|---|
| 文章 | SQLite（`data.db`） | 頁面 loader（前台）、`/api/articles`（後台） | 後台 `/admin` |
| 海報圖 | `uploads/` | 瀏覽器直接讀 `/uploads/…` | 後台上傳 |
| 展覽、工作坊 | `src/data/*.json` | 頁面元件（打包時） | 改 JSON 後重新打包 |
| 報名活動 | `src/data/enrolls.js` | 報名頁 | 改檔案後重新打包 |
| 活動頁文案 | 各頁面檔 | — | 改頁面檔後重新打包 |

`src/data/article.json` 只在第一次啟動時匯入資料庫（`server/import-articles.js`），之後文章以資料庫為準。

### 資料庫（SQLite）文章表 `articles`

| 欄位 | 說明 |
|---|---|
| `id` | 自動編號（主鍵） |
| `slug` | 網址用識別碼。舊文章沿用 `ALUM-A00x`，新文章是 `a-{id}` |
| `title` | 標題 |
| `description` | 摘要／描述 |
| `date` | 日期（純文字，例：`04 08 2025`） |
| `location` | 分類／標籤（例：`校友特稿`） |
| `cover` | 海報圖網址（`/uploads/xxx`），可為空 |
| `blocks` | 內文區塊，存成 JSON 字串 |
| `created_at` | 建立時間，用於排序（新→舊） |

**`blocks` 的格式**：一個陣列，每個元素是 `{ "type": "subtitle" 或 "paragraph", "content": "文字" }`。

### API 端點（網站有子路徑時，前面要加上子路徑）

| 方法 | 路徑 | 用途 | 需登入 |
|---|---|---|---|
| POST | `/api/login` | 管理員登入，回傳 token | ✗ |
| GET | `/api/articles` | 文章列表（不含內文，省流量） | ✗ |
| GET | `/api/articles/:slug` | 單篇文章（含內文區塊） | ✗ |
| POST | `/api/articles` | 新增文章（可上傳海報） | ✓ |
| PUT | `/api/articles/:id` | 更新文章（保留 slug，可換海報） | ✓ |
| DELETE | `/api/articles/:id` | 刪除文章（連海報檔一起刪） | ✓ |

## 網站子路徑（BASE_PATH）

網站可以掛在網域根目錄，也可以掛在子路徑（例如 `/tsio-design/`）。**只有一個設定來源**：

```
server/.env（本機）或 專案根目錄 .env（Docker）的 BASE_PATH
        │  由 server/env.js 讀取
        ├─► vite.config.js         base（JS、CSS、圖片網址）
        ├─► react-router.config.js basename（頁面網址）
        └─► server/config.js       Express 路由前綴（API、上傳圖）
```

前端程式裡要組 API 或上傳圖的網址時，一律用 `src/lib/paths.js` 的 `url()`，子路徑會自動接上。

## 分享預覽（LINE / FB）

- 每頁的分享資訊寫在頁面檔的 `meta`，用 `src/lib/meta.js` 的 `pageMeta()` 產生。
- 預覽圖：圖片網址加 `?og`（例：`import og from "../assets/imgs/about.webp?og"`），打包時由 `vite-imagetools` 置中裁成 1200×630 的 jpg。
- 置中裁會切到重點的寬橫幅，另存一張已裁成 1200:630 比例的圖到 `src/assets/og/` 再加 `?og`。
- 分享網址用的網域在 `src/config/site.js` 的 `SITE.origin`。

## 樣式與動畫

- **Tailwind CSS v4**，全站樣式與字級在 `src/App.css`。
- **設計參數**：動畫時長／曲線在 `src/config/motion.js`，區塊間距在 `src/config/spacing.js`。`root.jsx` 會把它們轉成 CSS 變數直接寫進每頁的 `<head>`，Tailwind class 以 `var(--motion-base)`、`mt-[var(--title-gap)]` 這類寫法讀取。
- **捲動進場**：帶有 `.headline` class 的元素捲進畫面時由下往上淡入（`src/hooks/useScrollReveal.js`，在 `App.jsx` 啟用一次、全站生效）。只有 JavaScript 有執行時才會先隱藏，搜尋引擎與關閉 JS 的瀏覽器會直接看到內容。
- **換頁淡入**：`src/small_component/PageTransition.jsx` + `App.css` 的 `.page-enter`。

## 寫程式要注意的規則

因為頁面會先在伺服器（Node）上產生，**元件在「渲染」階段不能使用只有瀏覽器才有的東西**：

| 不要在渲染時用 | 原因 | 改成 |
|---|---|---|
| `window`、`document`、`sessionStorage` | 伺服器上不存在，打包或開頁會直接報錯 | 放進 `useEffect`（只在瀏覽器執行） |
| 用 JS 量螢幕寬度決定版型 | 伺服器不知道螢幕多寬，手機會先看到桌機版再跳動 | 兩種版型都輸出，用 Tailwind 的 `md:hidden`、`hidden lg:flex` 切換 |
| 每次渲染結果不同的值（亂數、目前時間） | 伺服器與瀏覽器算出來不一樣，React 會回報不一致 | 放進 `useEffect` 後再設定 |

後台 `src/admin/AdminApp.jsx` 就是例子：登入狀態存在 `sessionStorage`，所以等瀏覽器端確認後才決定顯示登入頁或管理面板。

## 圖片

- 新增照片後跑 `npm run optimize:images`：長邊超過 2560px 的縮小、jpg／png 轉成 webp（轉檔後依提示更新 import 的副檔名）。
- 展覽、工作坊的封面：JSON 的 `cover` 欄位填 `src/assets/imgs/` 裡的檔名，由 `src/data/covers.js` 對應成網址。
- 首頁 Banner 的手機／平板圖放在 `src/assets/banner/mobile`、`tablet`，檔名含數字就決定輪播順序（`Banner.jsx` 會自動讀整個資料夾）。

## 常用指令

| 指令 | 用途 |
|---|---|
| `npm run dev` | 開發模式（網站 + API，前端存檔即時更新；改後端程式要重啟） |
| `npm run build` | 打包到 `build/`（含預先產生的頁面） |
| `npm start` | 用正式模式執行打包結果 |
| `npm run lint` | 程式碼檢查 |
| `npm run import:articles` | 把 `article.json` 匯入資料庫（資料庫已有文章會略過） |
| `npm run optimize:images` | 壓縮 `src/assets` 裡的圖片 |
